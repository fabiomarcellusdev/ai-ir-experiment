Configuring retries

When a handler throws, Courier puts the message back on the queue and tries again later. This page explains how the delay grows, how to cap the number of attempts, and how to send a message to the dead-letter queue when it keeps failing.

Backoff

The delay before attempt n is base * factor^(n-1), plus a random jitter of up to 20 percent. The defaults are a base of 500 ms and a factor of 2, so the first five delays are about 0.5, 1, 2, 4 and 8 seconds.

import { Queue } from '@courier/core';

const queue = new Queue('emails', {
  retry: {
    attempts: 5,
    backoff: { type: 'exponential', base: 500, factor: 2 },
    jitter: 0.2,
  },
});

Set jitter to 0 in tests, so that delays are repeatable.

Note: a retry is not free. Each attempt runs the handler again, so the handler must be idempotent. If it charges a card or sends an email, store a key and check it first.

When to give up

After the last attempt, Courier moves the message to the dead-letter queue. You can also stop early: throw a FatalError and Courier skips the remaining attempts.

  1. Throw FatalError for input that can never succeed, such as a malformed address.
  2. Throw any other error for a failure that may pass later, such as a timeout.
  3. Watch the courier_dead_letters_total metric and alert when it grows.
