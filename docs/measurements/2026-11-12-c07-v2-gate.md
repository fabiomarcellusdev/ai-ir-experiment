## Independent check

The `analysis-checker` agent recomputed the gate from the raw runs and the contract text, without the file's
`analysis` field. It got **PASS**, and every number above matches to rounding.

1. **Counts:** 240 runs, each task and arm with repeats 1 to 3, 1 attempt each, all on `db66899`. All 40 targets
   meet C0.7's limits (2,018 to 40,732 bytes; Read tokens at most 16,894).
2. **Transcripts:** the tokens, turns and cost of all 240 runs match the result lines of their transcripts. The
   checker did not judge the edits again; it took each run's `pass` as given.
3. **Noise:** the 3 rounds alone give median ratios of 0.384, 0.402 and 0.376. Only 2 of 37 tasks are above 0.70.
   The file medians go from 0.21 to 0.58. The success difference (+10 points, interval +2.5 to +20.8) is outside the
   noise; the replacement difference (+1.7 points, 1 run) is not.
4. **Where the code fills a point that the contract leaves open** (none changes the verdict):
   - the interval uses the nearest rank and C0.5's generator; another method gives the same interval to 3 decimals;
   - the success and type checks allow `1e-12` for rounding;
   - the bootstrap does not apply the 20-task minimum inside a resample (each resample has 27 or more tasks);
   - the qualifying rule leaves out the 3 tasks where M gained most; the median over all runs (0.406) shows no effect.
5. **A limit of the task set:** in files 5 and 7, one target (`tbody`) is inside another (`table`). The contract asks
   for 4 different targets, so the task set is valid, but the tasks of one file are not fully independent.
6. **One refused call:** in `5-replacement-1`, arm B, run 2, the agent called `Write`. The harness refused it
   ("No such tool available"), and the run then passed.
