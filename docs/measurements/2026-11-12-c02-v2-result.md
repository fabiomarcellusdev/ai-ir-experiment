# Gate C0.2 v2 result: hostile files with the v2 tools

**GATE VERDICT: PASS, on the second gate run.** The first gate run **FAILED** (2 calls reached the server's time
limit). The server was fixed, and the second run on commit `20cb98d` had 0 failures in 1,290 calls. All 8 negative
controls made the gate fail on their own cases (`docs/contract.md`, amendment "the gate text for the v2 tools", B).

## Conditions

- Date: 2026-11-12 (UTC). **TIMED.** Machine: Windows 11 (10.0.26300), AMD Ryzen 9 9950X3D (16 cores, 32 threads),
  66 GB of memory; a fast desktop, faster than an ordinary developer laptop. Node 24.22.1, parse5 8.0.1; the oracles are
  html5lib 1.1 (C0.2's and C0.1 v2's), parser only.
- Command: `node experiments/c02/run-c02-v2.mjs`, on committed code. Raw result: `experiments/c02/c02-v2-result.json`
  (the second run; no file text).
- Inputs: C0.2's 14 hostile files and 5 more (`tests/gates/hostile-v2.mjs`: ids on and around hidden content, an
  `img` with a 100 KB `data:` URI in an id listing, 20,000 cells of one tag, an element with an id and 80,000
  children, a 1.5 MB text node). Each case ran 5 times, each time in a new workspace.
- **Before the gate runs:** development runs found defects in the gate script (a word picker that did not end on a
  long text, checks of C0.2 that were left out, a no-file case that changed its file before a read); an independent
  review of the script found 9 points (the main one: condition 5 was never checked); all are fixed with tests.

## The first gate run: FAIL

On commit `4648f89`, in run 5 of 5, `set_attribute` and `replace_text` on the 1.9 MB file of fostered table rows
reached the server's limit of 1.5 s (the slowest call took 1,836 ms). C0.2 counts a call that reaches the server's
limit as a failure (C0.2 amendment of 2026-11-11, 2). Every other check passed, and all 8 controls failed. The result
is commit `452aa92`.

**The cause and the fix:** each v2 call built the server's whole view of the file again, also right after a find or
an outline of the same bytes. On this file the parse took about 0.1 s and the rest of the view (outline lines,
visible text, ranges) 0.2 to 0.35 s. Since commit `af59719`, v2 keeps its last view for the next call on the same
file with the same text (`viewOf`, `server/v2.mjs`, with a regression test). An earlier fix in the same run of work
keeps each element's marker parse in its view (commit `9619078`). C0.1 v2 passed again on `af59719`.

## What these numbers do not show

- **A slower machine.** The timings come from a fast desktop. The worst call took 427 ms; a machine 4 times slower
  would still be under the server's 1.5 s limit, but this is an estimate, not a measurement.
- **The first call on a large file.** The kept view helps a call that follows another on the same bytes. A first
  change on a 1.9 MB file builds the view once (about 0.5 s here).
- **Other hostile inputs.** The set is C0.2's set and 5 files more; it is not a fuzzer.
