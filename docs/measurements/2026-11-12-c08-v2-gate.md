## What the run shows

1. **A target named by its position is where the reading view helps most after large targets.** Arm B has no
   structure to count with: it reads the file, or large parts of it, to count the child elements of the named element. It read the whole
   file in 23 runs. Arm M asks the server for the structure and needs a median of 2 turns, against 4.
2. **The result is outside the noise.** The upper end of the interval (0.554) is well under 0.70.
3. **Success is equal.** Both arms passed all 120 runs.

## What these numbers do not show

- **How often real work names a target by position.** The task kind is chosen to suit the reading view. The gate
  measures this kind, not its share of a developer's work.
- **Other models or harnesses.** One model and one harness version ran.
- **Real work.** The tasks are single edits on single files, with a prompt that names the target.
- **The cost with deferred tool loading.** The tool text was in every turn of arm M (`ENABLE_TOOL_SEARCH=false`).
