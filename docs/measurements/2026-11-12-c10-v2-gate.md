## The stop

The gate stopped once, with no verdict, and went on at the same commit, as the contract's stop rule says (amendment
of 2026-11-12, C0.6 rule 2).

1. During the gate, the Claude Code on this machine updated itself to 2.1.323. The runs set `DISABLE_AUTOUPDATER=1`,
   so the update most likely came from another Claude Code process, such as the lead's session (a guess, not
   checked). The installed `claude` command then started 2.1.323.
2. At run 229 (`2-attribute`, arm B, run 3), the runner found 2.1.323 in the run's start message. It stopped the gate
   after 228 records and wrote a stop line, with the attempt's cost ($0.007).
3. The owner chose to finish with the kept 2.1.322 (2026-11-12). Claude Code keeps each installed version in
   `~/.local/share/claude/versions/`. The lead copied `2.1.322` from there to a folder in the session's scratchpad, as
   `claude.exe`, and put that folder first on the runner's PATH. Nothing was downloaded. The copy's SHA-256 is the
   same as the kept file's, and the copy reports `2.1.322 (Claude Code)`.
4. The lead checked out `540f2d4` with a detached HEAD, and the gate went on at 22:20. It ran run 229 again and the 11
   other runs.

All 240 records come from runs on 2.1.322. The runner checks the version of each run at its start.

## What the run shows

1. **On small tasks, the v2 tools cost more tokens than they save.** Both arms need a median of 3 turns. Arm B finds a
   small target with Grep and edits it with Edit, without a whole-file read. Arm M sends the same number of turns, and
   each turn also carries the text of the 3 v2 tools. The median run of arm M has about 3,000 more tokens.
2. **v2 improved on v1 for this task kind,** from 1.40 (C0.6) to 1.207, but not to 1.00.
3. **The result is not near the limit.** The whole interval (1.193 to 1.222) is above 1.00, so the failure is outside
   the noise.

## What these numbers do not show

- **The cost with deferred tool loading.** The tool text was in every turn of arm M (`ENABLE_TOOL_SEARCH=false`). With
  definitions that load only when needed, the overhead on small tasks could be smaller. This run does not measure it.
- **Other models or harnesses.** One model and one harness version ran.
- **Real work.** The tasks are single edits on single files, with a prompt that names the target.
