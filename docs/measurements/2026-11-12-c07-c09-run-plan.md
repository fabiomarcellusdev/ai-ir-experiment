## The lead's readings of the gate text

These do not change a number. The owner is told in the hand-over.

1. **The task rule of a draw** ("the file can give the gate's 4 tasks") is checked exactly: each of the 4 tasks can
   get a different valid target (a matching). For C0.9, both the removal and the insertion must work, because the
   file number is not known in the draw. When the task script's draw of a file reaches a task with no target left, it
   draws the file's 4 tasks again with the same stream, at most 100 times; a task records how many tries it took.
2. **The draw from the full list of valid targets:** the task script shuffles the type's targets with the gate's
   seed, and then each target's attributes (for a question or an attribute change). The first target with a valid
   unit (the oracle and, for C0.7, the token count) gives the task. That is a uniform draw over the valid targets,
   without checking every candidate with the oracle (review, 3).
3. **C0.7's quote** comes from the first visible text node inside the target, in document order, whose first 6 words
   (3 to 5 when it has fewer) meet the quote rules. This is C0.3's way to take a quote.
4. **C0.9's quote** for a target is the first valid window of 3 to 6 words in the visible text (by its start, longer
   first) whose deepest holder is the target. A text change uses the first such window that lies in one text node.
   `html_find` must give exactly 1 match, the target.
5. **A replacement or an insertion must give the new `p` after parsing** (C0.3's insertion rule): in a `select`, for
   example, the parser drops it.
6. **The attributes of a question or an attribute change, in C0.8 and C0.9:** a source location, a name of at most
   40 characters, and a value of 1 to 80 characters with no `"`, backtick, line break, or space at either end. The
   judge trims an answer, and a committed task set must hold no long third-party text (security review, F1). For
   C0.9 this is stricter than C0.4's "one attribute of the target".
6a. **Lengths:** a quote has at most 80 characters, and a C0.8 id at most 40. A target's tag name, and C0.8's T,
   match `^[a-z][a-z0-9-]{0,39}$`. A stored base name starts with a letter or a digit and has at most 100 characters
   (security review, F1 and F7; review, 5).
6b. **C0.7's quote** also starts and ends at word boundaries of the visible text: text of a neighbour element must
   not join its first or last word (review, 2).
6c. **C0.9's causes:** an entity is a source range of more than one character that starts with `&`, and it must decode
   to an allowed character (`&#9;` does not). A hidden inline element inside the quote makes the quote not valid,
   because its text is not visible (review, 7 and 8).
7. **Visible text** is the server's: text inside an `iframe`, for example, counts, as in `html_find`.
8. **The Read token count of C0.7** counts Read's output for the target's lines (`<line number>`, a tab, the line) as
   one user message with `count_tokens` and the model `claude-sonnet-5-5`.
