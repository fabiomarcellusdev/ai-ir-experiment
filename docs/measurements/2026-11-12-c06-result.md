# Gate C0.6 result: real agents, with and without the reading-view MCP server

**GATE VERDICT: FAIL.** Real agents with the MCP server used a median of **1.40 times** the tokens of agents with
the file tools alone (95% interval over files 1.14 to 1.92). The gate passes at 0.70 or less
(`docs/contract.md`, "C0.6"). Success was the same: B 117 of 120 runs, M 120 of 120. The success rules pass; the
token rule fails, so the gate fails.

**The viability answer of the experiment, as the gates define it: the reading view, as an MCP server for an agent
that edits HTML files, does not reduce the agent's tokens. It increases them.** C0.3 (the ideal path with the tool
definitions) failed at 0.739; C0.5 (the ideal path without them) passed at 0.374; C0.6 (real agents) fails at 1.40.

- **Independent check:** the `analysis-checker` agent recomputed every number from the 240 records with its own code

## Why the MCP arm used more tokens

1. **The baseline agent rarely reads whole files.** It searched with Grep for the quoted words, read a few lines when
   it needed them, and edited: 3 whole-file reads in 120 runs. C0.6's reason to expect a saving was that real agents
   read much more than the ideal path (contract, "Why these numbers"). They did not.
2. **The MCP agent took more turns:** typically Glob, `html_find`, `html_read`, `html_edit`, 5 turns against 3.5. It
   never called `html_outline`. 8 of its 120 runs used no MCP tool, and 17 used the built-in Edit.
   Each turn sends the conversation again, and the gate counts each cached token as one token.
3. **The MCP tool definitions** add about 720 tokens to every request.

In dollars the two arms cost the same ($1.31 and $1.30), because most tokens are cache reads at a twentieth of the
input price. The gate counts tokens, not dollars (contract, "What the rescope gates do not judge").

## After the gate: the file names favoured the MCP arm (exploratory, 2026-11-12)

This section was added after the verdict. It is not a gate rule, and it does not change the verdict.

The gate files have names that start with a number and a hyphen (`1-build.html`). The agent sometimes called a tool
with the name without its number (`build.html`). The call failed with a missing-file error ("File does not exist" from
Read and Edit, "Path does not exist" from Grep, "the file is not found" from the MCP server). The agent then needed
more turns to find the real name. This check calls such a run a run with a **misread name**.

| Measure | B | M |
|---|---|---|
| Runs with a missing-file error | 50 of 120 | 17 of 120 |
| Of these, runs with a misread name | 50 | 17 |
| The call just before the first misread name | Grep in 50 | Grep in 10, Glob in 7 |
| Runs with a misread name, by task type (question, text, attribute, structure; 30 runs each) | 2, 24, 14, 10 | 3, 10, 4, 0 |
| Median turns, runs with a misread name | 6 | 7 |
| Median turns, runs without one | 3 | 5 |

| Token ratio M ÷ B (median over tasks) | Tasks | Value | Tasks at 0.70 or less |
|---|---|---|---|
| Passed runs (the gate's rule) | 39 | 1.40 | 2 |
| Passed runs without a misread name, in both arms | 25 | 1.96 | 0 |

So most tasks where the MCP arm used fewer tokens were tasks where the baseline lost turns to a misread name: 9 of the
12 tasks with a ratio below 1.00 drop out of the second ratio. Without the misread names, the MCP arm used about
twice the baseline's tokens. 14 tasks drop out of the second ratio, because every passed run of one arm had a misread
name: the baseline in 10 tasks, the MCP arm in 2 (`4-question`, `4-attribute`), both arms in 2.

The check does not show why the agent misread the names. 60 of the 67 misread names came right after a Grep call, whose
output puts the name before a colon and a line number (`1-build.html:250:`). The other 7 came after a Glob call. The
lead's guess: the number prefix is the cause, and Grep's output format makes it worse.

- Command: `node experiments/c06/wrong-name.mjs`. It reads the git-ignored raw streams, so it runs only on the
  machine that ran the gate. NOT timed, free.
- What it does not show: a run without a misread name is not a random sample. It can be easier than a run with one.
  The second ratio compares 70 of B's 120 runs with 103 of M's. A gate with other file names would need a new run.

## What these numbers do not show

- **Other models, prompts and harnesses.** One model, one harness version, and the contract's prompts, which quote
  the text of the target. A task that does not quote the target text could favour the reading view.
- **Other ways to count.** The gate counts each cached token as one token. A count in dollars shows no difference.
- **Other tasks.** Edits to one element in one file; no task needs the page's structure as a whole.
- **The token parts.** The records keep each run's sum of input, cache-write, cache-read and output tokens, not
  the parts; the raw streams (git-ignored) hold them.
- **The 3 failed baseline runs** are one task. They change no rule's result: with them counted as passes, the
  task's ratio would be about 1.96, and the gate still fails.
- **The same agents with more instruction.** The MCP text is fixed (C0.6, rule 3): the agents got no advice on which
  tools to prefer.
