## What the numbers show

- **The gate passes, beyond the spread between files.** The interval's top, 0.472, is below 0.50. 29 of 40 tasks are
  at 0.50 or less.
- **The hypothesis from C0.3 held on fresh files.** C0.3's tasks gave 0.374 with the same definition, and the fresh
  draw also gives 0.374. The two sets share no file, so the equal value is probably a coincidence.
- **Edits gain most; questions lose.** For text, attribute and structure changes the MCP's work is about a quarter to a
  half of the baseline's. For questions, the median is 1.094: when Grep's matched line already shows the start tag,
  Grep alone answers, while the MCP still needs `html_find` and `html_read`, because the view does not show `class`.
- **With the tool definitions counted, nothing changed from C0.3.** The ratio as C0.3 computed it is 0.721; C0.3 gave
  0.739. The fixed cost of the definitions still outweighs the saving on one task in one request.
- **The extremes come from the path rules.** The lowest ratio (0.001) is a question on a 296 KB icon preview page:
  Grep found the quote on 2 lines far apart, and the baseline's one read spans from the first hit to the last
  (about 157,000 work tokens). The highest (1.985) are questions where Grep alone answers.

## What the numbers do not show

- **What a real agent does.** The paths are ideal. C0.6 measures real agents, with the MCP's tools added to the
  baseline's (3,514 tokens of definitions on every turn against 2,795).
- **A saving per session.** The work ratio leaves out the tool definitions, which a real session sends with every
  request.

## Known limits of the draw

- Some picks are not typical pages: an icon-font preview page (296 KB, app kind) and a Blogger theme partial with
  `<b:...>` tags (blog kind). The template rule finds `{{`, `{%`, `<%` and `<?php` only. The draw's rules were fixed
  before it ran, so the draw stands.
- The noise check found identical repeats on 5 requests; a repeat of all requests was not run. The record keeps only
  the result of the check, not its 15 counts.
- The runner does not refuse a second run. The commit (12:32:05 UTC) and the run (12:32:41 UTC) agree with one run,
  but do not prove it. The fix for C0.6 is in `docs/follow-ups.md`.
- The task rule leaves questions about `class` in the set. The view does not show `class`, so those questions need
  `html_read` in the MCP arm.
