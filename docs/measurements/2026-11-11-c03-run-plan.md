# Run plan: gate C0.3 (ideal-path tokens)

Written and committed before the preview and the run. The gate, its number (median ≤ 0.50) and its analysis are in
`docs/contract.md`. This file fixes what the contract left to the run plan, and the choices the code makes. An
independent review of the code (2026-11-11) found 13 findings; the fixes are in the code, and this plan names them.

## Fixed inputs

- **Frozen files:** `experiments/c03/run-inputs.json` holds the SHA-256 of the task set, both tool files and the three
  code files. The runner checks each hash, the 10 gate files' hashes in `file-set.json`, the task count (40), and
  that `experiments/c03/` and `docs/contract.md` have no uncommitted change. It stops if one check fails.
- **File set:** `experiments/c03/file-set.json` (5 kinds × 2 files, seed `20261110`, drawn 2026-11-11 at pinned commits).
  The files are in `experiments/gate-files/` (git-ignored).
- **Task set:** `experiments/c03/tasks.json`, made by `experiments/c03/make-tasks.mjs`. 40 tasks, 4 for each file.
  Offsets are UTF-16 code units of the file as text, not bytes.
- **Model:** `claude-sonnet-5-5`, through Anthropic's `count_tokens` endpoint (`anthropic-version: 2023-06-01`).
- **Tool definitions:**
  - B: the Read, Edit, Grep and Glob definitions of the harness that wrote this plan (Claude Code, 2026-11-11), in
    `experiments/c03/baseline-tools.json`. It is git-ignored because it is Anthropic's text.
  - M: Grep and Glob (the same definitions), plus `experiments/c03/mcp-tools.json`. The result holds only for a server
    that ships these definitions as they are.

## The harness limits used for B

- Read returns at most 2,000 lines a call, in `cat -n` form, with each line cut at 2,000 characters.
- Read's other size limit (the `allow_large` flag) is not modelled. A real harness can refuse a large chunk; then B
  needs the flag or more calls, a small cost that the run leaves out. This favours B.
- B's Grep path: one Grep in content mode with line numbers, for the quote as a literal (regular-expression
  characters escaped), then one Read from 20 lines before the first match to 20 lines after the last match. It is
  valid only when that Read holds every byte the task needs: the target's start tag for a question; the edit's
  `old_string`, and the whole element for a removal.
- B's edit: the Edit tool, with the first unique `old_string` around the change. The window grows 8 code units a
  step on each side, and its edges never split a surrogate pair. An insertion starts with one character before the
  point.

## Choices in the prototype and the task draw

1. **Every element has its own outline line.** Inline elements are not packed into their parent's line, so every
   element has a ref.
2. **Outline pages** are cut at 60,000 characters, as a stand-in for 20,000 tokens (at least 3 characters a token,
   not measured). `html_find` output has no page limit; at most 20 matches keep it short.
3. **The outline leaves out** `script`, `style`, `noscript`, `template`, `link`, `meta`, comments, SVG content, and the
   hidden content of the contract's list. Visible text also leaves out `noscript`, which the contract's list does not
   name. Line breaks and tabs in attribute values are written as `&#10;`, `&#13;` and `&#9;`.
4. **A target has an explicit end tag.** parse5 gives no exact end for an implied one.
5. **A target's quote** is the first 6 words of its first direct text node that has a word, as written in the source.
   The target is a deepest element that holds its quote, and no other element of its tag holds it. So the prompt's
   "the `<tag>` element that contains the text" names one element, and one Grep can find the quote on a line.
6. **A text change uses a text node that is a direct child of the target.** Its quote is the node's first 6 words.
   No other element outside the target's ancestors holds that quote.
7. **An insertion** is drawn only where the parsed expected file has one more `<p>` than the original (inside a
   `<select>`, parsing drops it).
8. **M's edit** sends the target's new HTML: the node with the change, an empty string to remove, or the node plus
   `<p>New text</p>` to insert after it.
9. **Each path is a list of API messages:** the user's prompt (the task prompt plus "The file is /work/page.html."),
   then a tool call and its result for each step, then the final edit call or the `ANSWER:` line, then a short user
   turn (`ok`, as a tool result after an edit call). The last turn makes the request valid; both arms get it, so it
   moves the ratio toward 1. No system prompt. `count_tokens` counts the messages and the arm's tools together.
10. **The seeded generator** is `s = (s * 1103515245 + 12345) & 0x7fffffff`, high bits. In JavaScript the product
    passes 2^53 and loses its low bits, so it is not a true linear congruential generator. It is still deterministic,
    and the committed draws used it, so it stays.

## The preview and the run

1. **Preview (owner, 2026-11-11):** `node experiments/c03/run-c03.mjs --preview`. It counts each path with the POC's
   two offline proxies (A and B) on the frozen inputs, and writes `experiments/c03/c03-preview.json`. It is labelled
   "PREVIEW, not the gate verdict".
2. **API preflight:** before the gate run, `--selftest` style requests on non-gate files go to `count_tokens`, to
   check the request shape and the size of a 500 KB file's whole-file path. Their numbers are not gate numbers.
3. **The gate run:** `node experiments/c03/run-c03.mjs --api`. It reads the key from `.local/anthropic-api-key`
   (git-ignored) and never prints it. It runs once, on the same commit as the preview. It prints no number for a
   single task, and writes `experiments/c03/c03-result.json` with the commit and the input hashes. It does not save
   the requests, which hold third-party page text.

## Known limits, before the run

- The email files are templates with placeholders (`{{name}}`). The contract does not judge templates, but its file
  rules do not remove them. parse5 reads the placeholders as text.
- The searches return some repositories that do not fit their kind (for example, the "blog" files are e-commerce
  pages). The contract fixes the searches, so the draw stands.
- The B tool definitions are this harness's text on 2026-11-11; another version of the harness can differ.
