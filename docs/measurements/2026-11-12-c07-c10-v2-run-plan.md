## The lead's readings for C0.10

These do not change a number. The owner is told in the hand-over.

1. **C0.3's rules on the server's view.** "Holds the quote" means that the quote is in the element's part of the
   server's visible text (`server/view.mjs`). For each occurrence of the quote, the holders are the deepest shown
   element whose visible text holds the whole occurrence, and its shown ancestors. C0.3 used its own `html.mjs`.
2. **The target:** a shown element in `body` with an explicit end tag and a clean range. Its quote is C0.3's: the first
   6 words of its first direct text node that has a word, as written in that node's source. It is the deepest holder
   of each occurrence that it holds, and no other element of its tag holds an occurrence.
3. **The text change:** a direct text node of the target with 3 words or more gives its first 6 words. No element
   other than the target and its ancestors holds them.
4. **The second rescope's limits apply to C0.10:** a quote of at most 80 characters with no `"` and no backtick; a tag
   name that matches `^[a-z][a-z0-9-]{0,39}$`; the attribute rules of reading 6 of the second rescope's plan. C0.3
   allowed any attribute. The limits keep long third-party text out of the committed task sets.
5. **A quote with more than 50 occurrences** in the visible text gives no target and no text change. A quote that
   frequent cannot name one element of its tag, except in rare files; the cap keeps the task rule fast.
6. **New text and new values** are C0.3's: `Updated wording <n>` and `updated-value-<n>`, with the file number n.
7. **A text change's quote occurs once in the file's source** (contract amendment of 2026-11-12, "C0.10's text
   change"). The rule came after the v2 preview, whose task `10-text` was ambiguous; the preview's task set stays.

## The draws (added after the v2 previews)

The fill rule (contract, amendment of decision 0008, item 4) is in `drawAll` (`experiments/c07/draw-files.mjs`):

1. The first pass draws 2 files of each kind, in C0.3's kind order, as C0.5 did. A kind may give 0 or 1 file.
2. When the gate has fewer than 10 files, the fill draws the missing files from the kinds in C0.3's kind order, with
   the same stream: one file from each kind in turn, in rounds, until the gate has 10 files or a full round gives no
   file (owner, 2026-11-12; the contract's words allow this reading and "each kind until it runs out").
3. Each turn draws 1 file, so the same-repository fallback never runs in a fill. The fill reads no file that the draw
   already read, and takes no repository that the draw already picked (review of the fill rule, 1).
4. Each fill pick is marked `fill` with its round, and stays under its own kind; the record lists the fill's reads
   apart (`fillReadInDrawOrder`).
5. A draw with fewer than 6 files writes its record, and the gate gets no task set (`tasks.mjs`).
