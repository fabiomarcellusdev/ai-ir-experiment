## The second run

The first gate run passed on commit `057f994`. The server then changed: `element` keeps the result of an element's
marker parse in its view, so that a v2 change does not parse a 2 MB file 3 times (C0.2 v2's development run; commits
`9619078` and `cc7a052`). The agreed text needs C0.1 v2 to pass on the server that the gates use, so the gate ran
again on `cc7a052`. It gave the same numbers: 0 failures in 1,664 changes, the same accepted counts, and all 8
controls failing. `experiments/c01/c01-v2-result.json` holds the second run.

## What these numbers do not show

- **Only these 16 files and these argument lists.** The new HTML is C0.1's list, so `replace` and `insert_after` are
  often refused by design. `set_attribute` and `replace_text` draw from short fixed lists.
- **The oracle's known gaps:** html5lib 1.1 fails 180 of the 1,792 tree-construction tests (C0.1's result); none
  of those cases was found to differ from parse5 here (0 disagreements).
- **The locators are rare by id:** 7 random changes used an id alone, and 29 an id with a child; few elements in
  these files have a unique id.
- **Two controls fail only on their fixed case** (1 failure each): the random draw rarely reaches a reference
  bound or an ambiguous text, by design of the draw.
- **Not the hostile files:** C0.2 v2 checks those.
