# Gate C0.6 run plan: agent tasks with the MCP added

**Status: final (2026-11-12), after the pilot.** The pilot (11 paid runs: 1 stopped at the start check, 8 pilot runs and 2 direct checks, $0.18
in total) checked the settings below. The gate run waits for the owner's yes, and runs once (`docs/contract.md`,
rescope order, 5).

## The question and the gate

Does an agent with the reading-view MCP server use fewer tokens on HTML edits, at the same success? C0.6 rules:
`docs/contract.md`, "C0.4, agent tasks" with the changes in "C0.6, agent tasks with the MCP added". Pass: the median
token ratio M ÷ B is 0.70 or less over at least 20 tasks, M's success rate is at least B's minus 5 points, and no task
type has an M success rate more than 15 points below B's. The analysis is fixed in `experiments/c06/analysis.mjs`,
with tests at the boundaries.

## The inputs

- The rescope's 10 files and 40 tasks (`experiments/c05/tasks.json`), at their recorded SHA-256 values.
- 3 runs of each task in each arm: 240 runs, in 3 rounds (run k of each task is in round k). The order inside each
  round is random with the seed `20261111` (the rescope's seed).
- Each run is judged by `experiments/c06/judge.py` (html5lib 1.1, parser only): the contract's canonical DOM and byte
  rule for an edit, with the owner's layout-whitespace rule of 2026-11-12, and the last `ANSWER:` line for a
  question. A test (`experiments/c06/c06.test.mjs`) shows that the judge passes all 30 expected files and fails all 30
  original files.
- The runner checks the SHA-256 of each input file and each expected file before the gate run.

## The tool text is unchanged

The server's `tools/list` now holds `_meta: {"anthropic/maxResultSizeChars": 65000}` for each tool. Claude Code reads
`_meta`; the documentation lists it as Claude Code's own setting. The model-visible name, description and input
schema stay byte-identical to `experiments/c03/mcp-tools.json` (`server/protocol.test.mjs` checks this). The pilot
compares the tool list in the run's start message with the frozen names.

## Records

- `experiments/c06/c06-result.json`: one record for each run (ids, numbers, flags; no text of a file; a tool name
  outside the 8 known names counts as "other") and the analysis. The runner refuses to write a record or the result
  that holds the API key, forward or reversed. The runner refuses to run when this file exists (the follow-up of the C0.5 analysis check).
- `experiments/gate-files/c06-runs/` (git-ignored): each run's raw stream, and the progress file. A run that stops
  goes on from the progress file, on the same commit only; the result records how many runs came before the last
  start.

## Values from the pilot (2026-11-12)

1. **Cost:** 8 runs on 3 C0.3 tasks and the canary task, each in both arms, all passed: $0.004 to $0.023 a run,
   $0.08 in total. The C0.6 files are larger (up to 296 KB), so the estimate for the 240 runs is **$3 to $15**. The
   gate stops with no verdict when its runs have cost **$40**; the owner then decides.
2. **Each arm's fixed text** (the first request's input tokens): B 4,382 to 4,409; M 5,103 to 5,127. The MCP tool
   definitions add about 720 tokens to each request.
3. **Models:** `modelUsage` named only `claude-sonnet-5-5`. No background model ran.
4. **Confinement, checked directly:** arm B was asked to read the canary by a relative and by an absolute path.
   Claude Code refused both reads ("`--restricted` confines the file tools to the working directory"). In the
   canary task, the agent did not follow the injected text in either arm.
5. **The size declaration, checked directly:** `html_outline` on a C0.3 file with a 54,107-character page returned a
   54,122-character result inline.
6. **The stream format:** the start message holds `tools`, `mcp_servers`, `skills`, `plugins` and
   `claude_code_version`; the result message holds `modelUsage`, `total_cost_usd`, `num_turns`, `subtype` and
   `is_error`, as the runner reads them.

## The pilot's first start (2026-11-12)

1. **First paid run** (`1-text`, arm B; $0.007): the runner stopped the pilot at the start check. Arm B had only
   Read and Edit. Without Glob or Grep, the agent could not find the file. No record was kept, as the plan says.
2. **Free probes** (an invalid API key: Claude Code prints its start message, then fails before any model call):
   - `--bare` removes Grep and Glob, with or without `--restricted`. Without `--bare`, with `--restricted`, each arm
     has its expected tools: B the 4 file tools; M the 4 file tools and the 4 `html` tools, with the server
     `connected` at the start.
   - Without `--bare`, Claude Code lists 16 built-in skills, 42 commands, 3 built-in plugins and 5 subagent
     definitions. `--disable-slash-commands` removes the skills and the commands. The plugins and the subagent
     definitions stay; the agent has no tool to call them, and both arms have the same.
   - No `CLAUDE.md` or `AGENTS.md` lies at `C:\`.
3. **The change:** the runner uses `--restricted --disable-slash-commands` and no `--bare`, checks the parent folders
   for project notes before each run, and checks the skills and plugins at each start.
