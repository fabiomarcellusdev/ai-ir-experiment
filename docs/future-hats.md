# Future hats

Hats drafted now and moved into `AGENTS.md` when their trigger arrives. When a trigger arrives, say so, run the check
in `docs/hats.md` on the draft, and offer to move it in. When a task would be done better by a waiting hat, offer to
wear its draft for that task.

| Hat | Trigger | Draft |
|---|---|---|
| Release and open-source maintainer | The first public release | `docs/hats.md` |
| Documentation and developer-relations lead | The first outside user | `docs/hats.md` |
| Web platform engineer | The first work on HTML, CSS or a component framework | `docs/hats.md` |
| Operations engineer | The first deployed service | `docs/hats.md` |
| Accessibility | A user interface is planned | Keyboard focus, reduced motion, contrast (WCAG AA); CLI output never carries meaning by colour alone and respects `NO_COLOR` |

## Not hats

Business roles (legal, marketing, finance) are separate agents or people, never hats. A hat says when a real expert is
needed.
